# 手机界面改版验证（2026-09-14）

本轮复用 `gestures.ts`、现有命令协议、配对/令牌和 Rust 控制适配层。手机端改为紧凑顶栏、弹性触控板、音量行、播放行、底部三个操作入口；键盘、窗口切换、更多、设置使用原生 dialog 底部面板。

- 默认深色中性表面，薄荷绿仅用于主操作和状态；图标使用 [Lucide 官方 Vue 包](https://lucide.dev/guide/vue) `@lucide/vue`，按需内联 SVG，无外部 CDN。
- 主页面使用动态视口高度和安全区；横屏双列，极小高度允许页面滚动。
- 面板使用原生模态隔离、焦点恢复、关闭/遮罩/Esc 退出；打开前释放手势、清空积累位移，关闭窗口选择会取消并释放 Alt。
- 使用 [VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport) 的 resize/scroll 跟随可见区域，输入区随软键盘压缩；不全局限制缩放。
- 文字草稿在关闭面板后保留；组词、等待确认期间不能再次发送；收到成功确认才清空，失败/超时保留文字。结果未知时不自动重发。
- 连接状态与传输事件对应，普通断线在顶栏显示；控制禁用，不再用常规断线 Toast 遮挡按钮。

## 已完成的浏览器验证

`npm run verify:mobile` 构建生产页面，运行 Chromium 手机模拟与确定性传输测试。测试服务设置严格 CSP，不开放任何系统控制。

- 320、360、375、390、430 CSS px 宽 × 550、650、750 CSS px 高共 15 组：主界面无滚动，所有按钮至少 44 × 44，触控板移动区至少 132 px（实际结果见 JSON）。
- 750 × 390 横屏；320 × 350 极小高度允许滚动访问底部。
- 常用按钮发出原有命令；连续窗口选择的 next/next/previous/confirm 顺序。
- 中文 composition 期间发送禁用；关闭再开草稿保留；成功确认清空、失败保留。
- 330 px 可见视口加 40 px 偏移的键盘收缩模拟，输入区域与发送按钮可见。
- 遮罩不穿透触控板；断线禁用；失败状态；重连不重放。
- 输出 `artifacts/mobile-ui/results.json` 和 main/keyboard/more/settings/offline/landscape 截图。

这是桌面 Chromium 模拟：传输及软键盘视口均为测试替身，不代表手机硬件键盘或真实 Wi-Fi 延迟验收。产品代码没有加入模拟状态或假成功路径。

## 真机补验（约 3 分钟）

1. 退出旧电脑程序后运行新版，手机重新加载页面。保留浏览器上下工具栏，竖屏确认常用操作同屏，横屏无裁切。
2. Android Chrome / iPhone Safari 分别打开「键盘」，确认系统键盘弹出后输入框和发送按钮可见；中文选词、换行、发送仅输入一次；关闭再开草稿保留。
3. 打开更多/设置，遮罩关闭不造成电脑点击。窗口切换连续选择第三个窗口，确认及取消均能释放 Alt。
4. 滑动中断 Wi-Fi、锁屏、切后台再返回，观察顶部断线/重连状态；恢复后不重放旧操作。重测真实鼠标手感。
5. 增大系统文字，检查小高度下可滚动找到全部控件；放大网页后仍可操作。

本轮界面测试不替代原有 Windows 系统控制验收，完整清单见 `docs/ACCEPTANCE.md`。
